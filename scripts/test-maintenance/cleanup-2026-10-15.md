# Unit-test cleanup plan — 2026-10-15

Baseline: commit `edf84292fdd79b77fd9835d9d17cc91fe4cfb849`; 179 test files and 4,341 test methods. The existing audit reports no exact-body duplicates, missing owners, discovery problems, or missing assertion paths. Manual inspection found semantic overlap and repeated binding matrices that the exact-body audit cannot detect.

## Implementation plan

1. Record a fresh full-suite/coverage baseline and retain the source inventory for comparison.
2. Consolidate NamedQuery binding tests across scalar, temporal, object, stream, and null-parameter groups. Use one shared table of parameter layouts, keeping distinct overloads and conversion/failure regressions separate. Replace count-only matchers with exact JDBC parameter positions and call order, verify fluent return values, and verify missing-name cleanup. Check stream/reader payloads at every repeated occurrence.
3. Remove verified redundant tests, recording their replacements. Consolidate the overlapping cs constant checks into individually reported parameterized cases while retaining every currently asserted constant.
4. Split ResultSetProxy's large mixed suite into core/wrapper, column access, cursor behavior, and update groups with one shared mock fixture. Keep index/label overloads adjacent and preserve distinct regression bodies.
5. Standardize changed classes: fields, setup/teardown, related cases, then helpers/fixture types; consistent imports, names for new tests, and behavior-oriented comments. Keep execution independent of source order.
6. Update the test guide and record before/after counts and duplicate dispositions. Run focused families, the source audit and its regression tests, the complete suite from a new build directory, and changed families in random method order. Compare production line/branch coverage and investigate any loss before completing.

## Completion criteria

- Every removed case has a documented surviving or stronger replacement.
- Moved cases remain discoverable and keep their fixture/ownership contract.
- Focused and full tests pass; the audit is clean.
- Consolidation does not reduce production coverage.
- Production code, coverage exclusions, and default suite selection stay unchanged.

## Implementation and results

All six plan steps are complete.

The NamedQuery binding families replace 271 repeated layout methods with 45 parameterized methods covering eight layouts each: single/repeated matches in the small-query path, one through four matches in the indexed path, and missing names in both paths. JDBC positions and call order are explicit. Missing names must close the statement exactly once without binding anything. Repeated streams/readers are consumed to verify every payload, including Unicode reader data.

Eight collection/array tests were renamed to distinguish direct overloads from values passed as Object. Four failure cases now assert exception identity, that later parameters are not bound, and the correct ownership contract: direct positional overloads retain caller ownership, while the Object overload closes after failure.

ResultSetProxy's mixed suite is now grouped as follows:

| Class | Cases |
| --- | ---: |
| ResultSetProxyTest: construction, wrappers, metadata, lifecycle | 10 |
| ResultSetProxyColumnAccessTest | 52 |
| ResultSetProxyObjectMappingTest | 51 |
| ResultSetProxyCursorTest | 20 |
| ResultSetProxyUpdateTest | 92 |

The five groups share ResultSetProxyTestSupport. Corresponding index/label cases are adjacent. Their surviving test bodies are unchanged.

### Duplicate dispositions

| Previous tests | Surviving or stronger coverage |
| --- | --- |
| NamedQuery setter methods ending in MapPath, MapBranch, or LoopBranch variants | The corresponding `set…_matchesNamedParameterPositions` method and ParameterLayout enum; distinct overloads remain separate |
| Both named SQL-null/type-name matrix spellings | `setNullTypeName_matchesNamedParameterPositions` |
| NamedQueryParameterBindingTest.testSetParameters_Map_NullThrows | `testSetParametersMapNull`, with the same Map overload and null input |
| NamedQueryScalarBindingTest.testSetBigDecimal_BigIntegerNull_DelegatesToSetNull | `testSetBigDecimalBigIntegerNull`, which also verifies the fluent return value |
| ResultSetProxyTest.testWrapNull | `proxyConstructorRejectsNullWhileTheFactoryStillAcceptsIt` |
| csTest's all-fields loop plus 81 individual constant tests | One parameterized contract, producing 172 distinct field cases; the 81 explicitly required names remain so removals still fail |

The constant source includes newly declared public String constants and deduplicates them against required names. Each field has an independent result, so a failure does not hide later constants.

The source comparison accounts for all 4,341 original JDBC test methods: 3,974 unchanged bodies, three helper-name substitutions, eight renamed/strengthened cases, and 356 methods replaced by the documented consolidations. No original method is unaccounted for.

### Reproduction

Standard commands from the repository root:

```powershell
mvn clean test jacoco:report
node scripts/test-maintenance.mjs --check --json target/test-inventory.json
node --test scripts/test-maintenance/test-maintenance.test.mjs
mvn '-Dtest=NamedQuery*Test,ResultSetProxy*Test,csTest' '-Djunit.jupiter.testmethod.order.default=org.junit.jupiter.api.MethodOrderer$Random' '-Djunit.jupiter.testclass.order.default=org.junit.jupiter.api.ClassOrderer$Random' '-Djunit.jupiter.execution.order.random.seed=20261015' '-Djacoco.skip=true' test
git diff --check
```

Validation used JDK 25 and Maven 3.9.16 with ignored copies of the current POM, absolute source/resource paths, and separate baseline/final build directories. Test JVMs were capped at 768 MiB and two active processors; dependencies, test selection, compiler settings, and coverage configuration were preserved. Both full-suite coverage runs used `-Djacoco.append=false`.

The final full-suite command was:

```powershell
mvn -o -l target/test-cleanup-2026-10-15/final-suite.log -f target/test-cleanup-2026-10-15/final-pom.xml '-Djacoco.append=false' test jacoco:report
```
